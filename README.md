# waveform-core

**A scrollable, music-scanned waveform core for Java.**
No Android dependency, no runtime libraries, no bitmap tiles.

> **한국어 요약** — 실제 음악 PCM을 **한 번 스캔**해 만든 파형 코어입니다. 전체 곡을 이어 붙인
> **스크롤 가능한 strip**과 중앙 playhead, 저역/고역 **dB 비율에서 나오는 색**, 에너지에서 나오는
> 밝기, 그리고 **곡 길이/줌에서 계산되는 크기**를 제공합니다. Android 클래스는 포함하지 않아
> 서버, 데스크톱, 다른 Android 앱 어디서든 같은 코어를 쓸 수 있습니다.

---

## Why this is different

- **Scrollable, whole-track geometry** — the waveform is one continuous strip, not a fixed
  window. The viewport is a moving window over `duration × zoom × density`; the playhead stays
  in the centre and `scroll ↔ time` is an exact inverse mapping.
- **Colour comes from the music** — low/high band energy is compared in **dB** over a ±12 dB
  span, so bass really reaches red (6°) and treble really reaches cyan (198°). Brightness is
  RMS energy; played/unplayed are separate pre-computed colours.
- **Size and shape are generated by scanning the track** — a single streaming decode produces
  **100 buckets/second** of `peak / RMS / low / high`. The strip width is derived from the
  scanned duration and the chosen zoom, and bar heights use the **p95** of the actual bucket
  peaks plus gain/gamma. The waveform is a measurement of the song, not a decoration.
- **Android-free core** — pure Java 17. The Android decoder/cache/view adapters stay in the
  app; this artifact is reusable from any JVM program.
- **Tested** — **61 JVM tests** covering bucket boundaries, silence/NaN, p95/gamma, zoom
  invariance, dB hue, HSV, geometry inverse mapping, ruler steps and interpolation.
- **No runtime dependencies** — only `JUnit 4.13.2` for tests; it is not in the JAR.

## Pipeline

```text
16-bit PCM (streaming)
      │  mono downmix
      ▼
WaveformMetrics.Accumulator          100 buckets / second (10 ms)
  peak = max|sample|                 → bar height material
  rms  = sqrt(mean(sample²))         → brightness
  low  = sqrt(mean(LPF(200 Hz)²))    ┐
  high = sqrt(mean((sample-low)²))   ┘→ hue material
      │
      ▼
WaveformBars.aggregate(wf, barCount)
  mean peak → p95 gain (≤8×) → min(1) → ^0.75
  low/high mean → dB difference / ±12 dB → hue
  played/unplayed ARGB pre-computed
      │
      ▼
WaveformGeometry
  strip width = duration × dpPerSecond × density (cap 8192 px)
  scroll ↔ time ↔ screen x, ruler step, 200 ms interpolation
```

## Modules

| Class | Responsibility |
|---|---|
| `WaveformMetrics` | 16-bit PCM → 100 Hz buckets (`peak`, `rms`, `low`, `high`), 200 Hz one-pole low-pass, 10 Hz DC tracker |
| `WaveformBars` | bucket → bar average, p95 + gain + gamma, hue balance, played/unplayed colours |
| `WaveformColor` | dB band balance, hue, RMS brightness, unplayed visibility, HSV→ARGB |
| `WaveformGeometry` | whole-track strip width/cap, scroll↔time, screen x↔time, ruler step, interpolation |
| `WaveformMath` | legacy peak accumulator, kept for compatibility |

Not included: `WaveformDecoder` (MediaCodec), `WaveformCache` (Android File/Context),
`WaveformLoader` (Handler/Executor), `WaveformView` (Canvas/View). Those are Android adapters
in the MusicSpeedLocal app and feed this core.

## Quick start

### 1. Scan PCM into buckets

```java
int buckets = WaveformMetrics.bucketCountFor(durationMs);
long monoSamples = durationMs * sampleRate / 1000L;

WaveformMetrics.Accumulator acc =
        new WaveformMetrics.Accumulator(buckets, monoSamples, sampleRate);

// shortPcm = 16-bit interleaved PCM; call this for each decoded buffer
acc.addInterleaved(shortPcm, offset, sampleCount, channelCount);

WaveformMetrics.Waveform wf = acc.finish();
```

`WaveformMetrics.Waveform` exposes `peaks`, `rms`, `low`, `high` and `length()`.
The decoder never has to keep the whole PCM stream in memory.

### 2. Build bars and colours

```java
int barCount = 80; // visible bars at the current zoom
WaveformBars bars = WaveformBars.aggregate(wf, barCount);

for (int i = 0; i < bars.count; i++) {
    float height = bars.amplitudeAt(i);       // 0..1, p95+gamma applied
    int played   = bars.playedColorAt(i);     // ARGB
    int unplayed = bars.unplayedColorAt(i);   // ARGB
}
```

### 3. Map time to scroll and screen x

```java
float density = 2.625f;   // screen density
float waveWidth = WaveformGeometry.waveWidthPx(durationMs, 5f, density);

float scroll = WaveformGeometry.scrollForTime(positionMs, durationMs, waveWidth);
long center  = WaveformGeometry.centerTimeMs(scroll, durationMs, waveWidth);

long start = WaveformGeometry.visibleStartMs(paddingLeft, viewportWidth, scroll,
        durationMs, waveWidth);
long end   = WaveformGeometry.visibleEndMs(paddingLeft, viewportWidth, scroll,
        durationMs, waveWidth);
```

## What is generated by scanning the music?

| Output | Source |
|---|---|
| Number of buckets | scanned duration × 100/s, clamped 2,000..120,000 |
| Bar heights | `peak` per bucket → bar mean → p95 gain (≤8×) → gamma 0.75 |
| Brightness | `rms` per bucket → sqrt-shaped value curve |
| Hue | `low`/`high` band energy → dB difference / ±12 dB → 6°..198° |
| Strip width | scanned duration × zoom (2.5/5/10 dp/s) × density, capped at 8,192 px |
| Ruler step | visible px per second, chosen so labels never overlap |
| Played/unplayed | position ratio, colours pre-computed from the same bar data |

## Measured readability (MusicSpeedLocal 1.6)

Measured with the original Android app's screenshot measurement tool, same 1× zoom:

| Track | Metric | 1.5 | 1.6 |
|---|---|---:|---:|
| Reference track A (dense pop) | bar height p95 | 0.545 | **0.683** |
| Reference track A (dense pop) | hue spread (p5–p95) | 37.1° | **156.3°** |
| Reference track B (high dynamic range) | bar height p95 | 0.210 | **0.447** |
| Reference track B (high dynamic range) | hue spread (p5–p95) | 25.9° | **150.4°** |

The colour gap is the headline change: 1.5 compressed hue into orange/green
(19.5°–125.1°), while dB band ratio plus no compression makes red↔cyan reachable.
Reference track B shows the remaining p95 limitation for material whose body is ~1% of
its transients; a 1.7 candidate is a p90/body-envelope or short-window RMS normaliser.

## Design notes

- **p95, not max**: the single loudest bucket must not decide the whole-track scale.
  A 1024-bin histogram computes the bucket peak p95; gain is capped at 8× (+18 dB).
- **Zoom invariance**: gain is computed once per bucket set, not per bar count. Changing
  `barCount` (zoom) does not change the height scale.
- **Average bars**: a bar is the mean of the buckets it covers. `max` over a long track
  turns almost every bar into a solid block.
- **No FFT**: a one-pole 200 Hz low-pass and its complement give a cheap, stable
  bass/treble split for colour.
- **No bitmap tiles**: the view can draw only visible bars; this core just supplies the
  numbers and colours.

## Constraints

- `WaveformMetrics` expects **16-bit PCM**. Reject float PCM in your decoder adapter rather
  than feeding garbage.
- `WaveformGeometry.MAX_WAVE_WIDTH_PX = 8192` caps very long strips; the time mapping remains
  exact inside the capped strip.
- This JAR does not persist a cache. If you need one, store the four float arrays plus
  duration/bucket count and validate them on load.
- Track-specific p95 can still be low for extremely percussive material; see the measured
  MFT result above.
